# API reference

Always-current, interactive documentation is generated by FastAPI (OpenAPI):
run `make backend` and open http://localhost:8000/docs. This page explains the
intent and the rules behind each endpoint.

General rules:
- Data that no source provided is `null` ("not available"), never `0` or placeholder text.
- Text fields come from external sources: render them as **plain text**, never as HTML.
- An invalid parameter returns **422** with an explanation, not an empty list.

## `GET /api/health`
Checks the API is running. Returns `{"status": "ok"}`.

## `GET /api/vulnerabilities`
Paginated list with filters and search. All parameters are optional and combine with AND.

| Parameter | Type | Meaning |
|-----------|------|---------|
| `added_from`, `added_to` | date `YYYY-MM-DD` | Date added to KEV, inclusive. `added_from` after `added_to` returns 422 |
| `technology` | text, repeatable | Name from `/api/technologies` (case-insensitive). Several values are OR-ed. Unknown name returns 422 listing the valid ones |
| `vendor`, `product` | text | Contains, case-insensitive |
| `min_cvss` | 0-10 | CVSS score at least this. Rows without a score are excluded |
| `severity` | `LOW` `MEDIUM` `HIGH` `CRITICAL`, repeatable | `?severity=HIGH&severity=CRITICAL` |
| `min_epss` | 0-1 | EPSS probability at least this |
| `ransomware` | boolean | `true`: known ransomware use. `false`: known *not* to be used. Unknown (`null`) matches neither |
| `q` | text (max 200) | Free text or CVE id: searches CVE id, title, description, vendor, product (contains, case-insensitive). `%` and `_` are taken literally |
| `sort` | `date_added` (default), `cvss`, `epss` | Rows without a value always come last |
| `order` | `desc` (default), `asc` | |
| `page`, `page_size` | int | Page from 1; size 1-100, default 25 |

Response: `{items: [...], total, page, page_size}`; `total` counts all matches, not only the page.
Each item has: `cve_id`, `title`, `vendor`, `product`, `cvss_score`, `severity`, `epss_score`,
`epss_percentile`, `is_kev`, `ransomware_use`, `date_added`, `technologies`.

Examples:
```
/api/vulnerabilities?technology=Java&min_epss=0.5&sort=epss
/api/vulnerabilities?severity=CRITICAL&ransomware=true&added_from=2025-01-01
/api/vulnerabilities?q=log4j
```

## `GET /api/vulnerabilities/{cve_id}`
Full detail: everything above plus `description`, `cvss_vector`, `published_at`,
`modified_at`, `kev_due_date` and `references` (http/https links).
The id is case-insensitive. **404** if the CVE is not in the database,
**422** if it is not a valid CVE id.

## `GET /api/technologies`
Technologies from `technologies.yaml`: `name`, `osv_ecosystems`, and `products`
(as `"Vendor / Product"`). Use `name` for the `technology` filter.

## `GET /api/advisories`
Package advisories (GitHub Advisory Database via OSV) for the ecosystems in
`technologies.yaml`. All parameters are optional and combine with AND.

| Parameter | Type | Meaning |
|-----------|------|---------|
| `technology` | text, repeatable | Name from `/api/technologies`; matches advisories affecting that technology's `osv_ecosystems`. Unknown name returns 422. A technology without ecosystems matches nothing |
| `package` | text | Package name contains, case-insensitive |
| `severity` | `LOW` `MEDIUM` `HIGH` `CRITICAL`, repeatable | |
| `min_epss` | 0-1 | Advisory EPSS at least this (highest of its CVEs). Advisories without a score are excluded |
| `published_from`, `published_to` | date | Inclusive. Inverted range returns 422 |
| `has_cve` | boolean | `true`: has a CVE. `false`: has none |
| `q` | text (max 200) | Searches the advisory id, summary, CVE ids and package names. `%` and `_` are literal |
| `sort` | `published` (default), `epss` | Rows without a value always come last |
| `order` | `desc` (default), `asc` | |
| `page`, `page_size` | int | Page from 1; size 1-100, default 25 |

Response: `{items, total, page, page_size}`. Each item: `id`, `summary`, `severity`,
`epss_score`, `epss_percentile`, `published_at`, `github_reviewed`, `cves`, `packages`
(`ecosystem`, `name`), `technologies`.

Examples:
```
/api/advisories?technology=Java&severity=CRITICAL&min_epss=0.9&sort=epss
/api/advisories?has_cve=false
/api/advisories?q=log4j-core
```

## `GET /api/advisories/{advisory_id}`
Full detail: everything above plus `details` (Markdown from the source: render as plain
text), `cvss_vector`, `modified_at`, `references`, `cves` (each with `in_database`: true when
that CVE has a page under `/api/vulnerabilities/{cve_id}`) and `packages`, each with
`fixed_versions` and `ranges` (OSV ranges, **not interpreted**). The id is case-insensitive.
**404** if unknown, **422** if it is not a `GHSA-xxxx-xxxx-xxxx` id.

## Advisories on a CVE
`GET /api/vulnerabilities/{cve_id}` also returns `advisories`: the package advisories that
mention that CVE (`id`, `summary`, `severity`, `packages`). Empty when there are none (most KEV CVEs).

## `GET /api/research/{cve_id}`
Investigates one CVE across every research source (see [research sources](research-sources.md)
and [ADR 0004](adr/0004-investigations-on-demand-and-snapshots.md)). Works for any CVE, in KEV
or not. Query parameter `refresh=true` ignores cached results.

Response: `cve_id`, `generated_at`, `sources` (a summary of every source consulted, with its
`status`) and `results` (one block per source: `source`, `source_name`, `status`, `message`,
`origin_url`, `retrieved_at`, `data`). `status` is `ok`, `no_data` or `error`; `message` says why
when it is not `ok`. Blocks are never merged. One failing source never fails the request: it is
an `error` block. The id is case-insensitive; **422** if it is not a valid CVE id (no source is
called). The shape of `data` depends on the source.

## Reports (`/api/reports`)
Saved investigations ([ADR 0004](adr/0004-investigations-on-demand-and-snapshots.md)). A report
holds a title, Markdown `notes`, a `status` (`open` / `done`), 1 to 10 CVEs and one saved block per
CVE and source (the same block shape as `/api/research`), stored as a snapshot.

| Endpoint | What it does |
|----------|--------------|
| `POST /api/reports` | `{title, cves, notes?}`: investigates every CVE and saves the answers. **201** |
| `GET /api/reports` | Reports by most recent update (no notes or blocks) |
| `GET /api/reports/{id}` | The report with its saved blocks. Queries nothing. **404** if unknown |
| `PATCH /api/reports/{id}` | Any of `title`, `notes`, `status`, `add_cves`, `remove_cves`. Added CVEs are investigated now; removed ones lose their blocks |
| `POST /api/reports/{id}/refresh` | Queries everything again (ignores the cache) and returns `{report, changes}` |
| `DELETE /api/reports/{id}` | Deletes the report. **204** |

- `changes` lists only what differs: `new`, `status`, `data` (with the top-level `fields` that
  changed) or `refresh_failed`. A source that fails during a refresh keeps its previous block,
  so a refresh never replaces good data with an error. Changes are not stored; they are returned once.
- CVE ids are normalized and de-duplicated; any invalid id gives **422** and nothing is saved.
  A report always keeps between 1 and 10 CVEs.
- `notes` are untrusted text (max 100,000 characters): clients render them without raw HTML.
- There is no login (out of scope in v1): anyone who can reach the API can edit or delete
  reports. CORS allows `GET`, `POST`, `PATCH` and `DELETE` from the configured origins only.
- Creating or refreshing takes a few seconds per CVE (all sources are queried).

## Implementation notes
- Routes: `api/routes.py` (KEV vulnerabilities, technologies), `api/advisories.py`, `api/research.py` and `api/reports.py`; shared
  dependencies: `api/deps.py`; response models: `api/schemas.py`; filter and sort logic: `queries.py`.
- All values reach SQL as bound parameters (no SQL injection).
- A technology filter expands to its vendor/product pairs from `technologies.yaml`
  (see [technologies](technologies.md)).
- Advisories are a separate resource from KEV vulnerabilities (see ADR 0003); they are linked by CVE id.
