# API reference

Always-current, interactive documentation is generated by FastAPI (OpenAPI):
run `make backend` and open http://localhost:8000/docs. This page explains the
intent and the rules behind each endpoint.

General rules:
- Data that no source provided is `null` ("not available"), never `0` or placeholder text.
- Text fields come from external sources: render them as **plain text**, never as HTML.
- An invalid parameter returns **422** with an explanation, not an empty list.

## `GET /api/health`
Checks the API is running. Returns `{"status": "ok"}`.

## `GET /api/vulnerabilities`
Paginated list with filters and search. All parameters are optional and combine with AND.

| Parameter | Type | Meaning |
|-----------|------|---------|
| `added_from`, `added_to` | date `YYYY-MM-DD` | Date added to KEV, inclusive. `added_from` after `added_to` returns 422 |
| `technology` | text, repeatable | Name from `/api/technologies` (case-insensitive). Several values are OR-ed. Unknown name returns 422 listing the valid ones |
| `vendor`, `product` | text | Contains, case-insensitive |
| `min_cvss` | 0-10 | CVSS score at least this. Rows without a score are excluded |
| `severity` | `LOW` `MEDIUM` `HIGH` `CRITICAL`, repeatable | `?severity=HIGH&severity=CRITICAL` |
| `min_epss` | 0-1 | EPSS probability at least this |
| `ransomware` | boolean | `true`: known ransomware use. `false`: known *not* to be used. Unknown (`null`) matches neither |
| `q` | text (max 200) | Free text or CVE id: searches CVE id, title, description, vendor, product (contains, case-insensitive). `%` and `_` are taken literally |
| `sort` | `date_added` (default), `cvss`, `epss` | Rows without a value always come last |
| `order` | `desc` (default), `asc` | |
| `page`, `page_size` | int | Page from 1; size 1-100, default 25 |

Response: `{items: [...], total, page, page_size}`; `total` counts all matches, not only the page.
Each item has: `cve_id`, `title`, `vendor`, `product`, `cvss_score`, `severity`, `epss_score`,
`epss_percentile`, `is_kev`, `ransomware_use`, `date_added`, `technologies`.

Examples:
```
/api/vulnerabilities?technology=Java&min_epss=0.5&sort=epss
/api/vulnerabilities?severity=CRITICAL&ransomware=true&added_from=2025-01-01
/api/vulnerabilities?q=log4j
```

## `GET /api/vulnerabilities/{cve_id}`
Full detail: everything above plus `description`, `cvss_vector`, `published_at`,
`modified_at`, `kev_due_date` and `references` (http/https links).
The id is case-insensitive. **404** if the CVE is not in the database,
**422** if it is not a valid CVE id.

## `GET /api/technologies`
Technologies from `technologies.yaml`: `name`, `osv_ecosystems`, and `products`
(as `"Vendor / Product"`). Use `name` for the `technology` filter.

## Implementation notes
- Routes: `backend/src/zero_cool_api/api/routes.py`; response models: `api/schemas.py`;
  filter and sort logic: `queries.py`.
- All values reach SQL as bound parameters (no SQL injection).
- A technology filter expands to its vendor/product pairs from `technologies.yaml`
  (see [technologies](technologies.md)).
- Package vulnerabilities from OSV and GitHub (v1b) will appear in the same endpoints.
